# Предложение по переносу семейного дерева с помощью ИИ

## Задача

У пользователя уже может быть семейное дерево:

- на другом генеалогическом сайте;
- в программе на компьютере;
- в таблице или текстовом документе;
- в PDF;
- в виде снимков экрана;
- на старой бумажной схеме или фотографии.

Не все сервисы позволяют выгрузить дерево в удобном формате. Повторно вводить десятки людей, даты и родственные связи вручную долго. Предлагается использовать ИИ для подготовки черновика дерева и последующего импорта в «Голос рода».

## Рекомендуемый подход

Создать на сайте мастер импорта семейного дерева. Пользователь выбирает источник, загружает материалы и получает предварительно собранное дерево.

ИИ не должен автоматически публиковать или окончательно сохранять сведения. Сначала пользователь просматривает людей, даты и связи, исправляет ошибки и только после этого подтверждает импорт.

## Способы переноса

### 1. Импорт готового файла

Если другой сервис позволяет выгрузить данные, пользователь загружает:

- GEDCOM — основной стандарт обмена генеалогическими данными;
- JSON установленного формата;
- CSV или таблицу;
- архив с данными и фотографиями, если такой формат поддерживается источником.

Это наиболее точный способ переноса, потому что имена, даты и родственные связи уже представлены как данные.

### 2. Распознавание фотографии или PDF

Пользователь загружает фотографию бумажного дерева, скан схемы, PDF, снимки экрана с другого сайта или фотографии отдельных карточек родственников.

ИИ распознаёт:

- фамилии, имена и отчества;
- даты рождения и смерти;
- места;
- подписи на схеме;
- расположение карточек;
- линии и предполагаемые родственные связи.

Результат отображается как черновик. Неуверенно распознанные сведения отдельно выделяются для проверки.

### 3. Подготовка JSON через внешний ИИ

Пользователю предоставляется готовая инструкция и пример JSON. Он может передать их вместе со своими фотографиями, PDF или текстом доступному ИИ-сервису.

ИИ возвращает файл JSON установленного формата. Пользователь загружает этот файл в «Голос рода» и просматривает предварительный результат.

Такой вариант можно использовать до появления полноценного встроенного распознавания.

### 4. Прямой перенос с другого сайта

Автоматическое копирование данных непосредственно с другого сайта является самым сложным вариантом. Оно зависит от устройства сайта, правил сервиса, наличия авторизации и разрешения пользователя.

Не рекомендуется начинать с автоматического сбора данных с чужих сайтов. Сначала следует поддержать официальные выгрузки, GEDCOM, JSON, PDF и снимки экрана.

Если прямой перенос всё же потребуется, пользователь должен самостоятельно войти в исходный сервис и явно разрешить перенос только своего дерева.

## Пользовательский поток встроенного импорта

1. Пользователь нажимает «Перенести семейное дерево».
2. Выбирает источник: файл, фотография, PDF, снимки экрана или текст.
3. Загружает материалы.
4. Система сохраняет исходные файлы отдельно от результата распознавания.
5. ИИ выделяет людей, даты, места и родственные связи.
6. Система создаёт черновик дерева.
7. Пользователь просматривает список найденных людей.
8. Исправляет имена и даты.
9. Подтверждает или меняет родственные связи.
10. Объединяет возможные дубли.
11. Просматривает дерево целиком.
12. Подтверждает импорт.
13. Система добавляет подтверждённые сведения в семейное пространство.
14. Исходные материалы остаются доступны как источники данных.

## Экран предварительной проверки

Перед импортом необходимо показать:

- количество найденных людей;
- количество найденных родственных связей;
- людей без дат;
- неуверенно распознанные имена;
- противоречивые даты;
- возможные дубли;
- связи, которые ИИ не смог определить;
- фрагмент исходного изображения для каждого распознанного значения.

Для каждой записи пользователь выбирает: подтвердить, исправить, пропустить или объединить с существующим человеком.

## Формат JSON

Файл должен содержать:

- версию формата;
- описание источника;
- список людей;
- имена и фамилии;
- даты и места рождения и смерти;
- список родственных связей;
- ссылки на исходные фрагменты;
- уровень уверенности ИИ;
- предупреждения и сведения, требующие проверки.

Пример находится в файле `ПРИМЕР-ИМПОРТА-СЕМЕЙНОГО-ДЕРЕВА.json`.

## Правила обработки данных

- Не придумывать отсутствующие имена, даты и связи.
- Не заменять неизвестные значения предположениями.
- Для каждого распознанного значения сохранять источник.
- Отдельно отмечать приблизительные даты.
- Показывать уровень уверенности распознавания.
- Не сохранять импорт без подтверждения пользователя.
- Не изменять существующее дерево без предварительного просмотра.
- Предупреждать о возможных дублях.
- Не использовать загруженные семейные данные для обучения внешних моделей без отдельного согласия.
- Указывать пользователю, какой внешний сервис обрабатывает материалы.
- Предоставить возможность удалить исходные файлы и черновик импорта.

## Предлагаемые этапы реализации

### Первый этап

1. Утвердить формат JSON.
2. Реализовать загрузку JSON.
3. Показывать предварительный список людей и связей.
4. Добавить подтверждение перед импортом.
5. Подготовить переносимую инструкцию для внешнего ИИ.

### Второй этап

1. Добавить импорт GEDCOM.
2. Добавить загрузку фотографий, PDF и снимков экрана.
3. Подключить распознавание имён, дат и связей.
4. Добавить экран исправления результата.
5. Добавить поиск дублей в существующем дереве.

### Третий этап

1. Исследовать официальные способы выгрузки из популярных сервисов.
2. Добавить отдельные преобразователи поддерживаемых форматов.
3. Оценить прямой перенос из сервисов, где он разрешён правилами и технически возможен.

## Что требуется оценить разработчику

1. Какие форматы импорта уже поддерживает текущая платформа.
2. Можно ли использовать GEDCOM как основной формат обмена.
3. Как будет выглядеть внутренний формат людей и родственных связей.
4. Где будут обрабатываться фотографии и PDF.
5. Как показать пользователю источник каждого распознанного значения.
6. Как обнаруживать дубли до сохранения.
7. Какой объём дерева допустимо обрабатывать за один импорт.
8. Как удалять черновики и исходные файлы.
9. Как оценить сроки и стоимость каждого этапа.

## Рекомендация

Начать с JSON и GEDCOM, потому что это управляемые и проверяемые форматы. Одновременно подготовить инструкцию для внешнего ИИ, которая позволит преобразовывать фотографии, PDF и текст в JSON. Встроенное распознавание изображений добавить следующим этапом после проверки процесса на реальных семейных деревьях.

## Статус

Предложение подготовлено и требует оценки разработчиком.
